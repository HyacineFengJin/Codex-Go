# 客户端限制审计（0.20.2）

原则：不添加缺少实际依据的产品配额，不用陈旧观察阻止点击，不静默丢失用户内容。大内容优先流式复制、分页和按需读取；保留边界必须说明资源、协议或权限依据。服务商本身的上下文、额度和模型限制按真实错误显示，客户端不另设每日次数、任务步数或 token 配额。

## 本轮移除

- 8 个附件 / 单文件 64 MB、50 个项目、20 条待处理分享、10 条排队消息。
- 分享、通知及悬浮窗输入的 128K 字符上限，手机输入的 10K 字符上限，项目 / 对话名称的 60 / 120 字上限。名称仍不能空白或含控制字符。
- 手机操作空闲 3 分钟就自动暂停。点击不依赖截图年龄或画面稳定。
- 流式回复、工具结果和完整 diff 的 64K 静默截断；完整长 diff 不再因长度而禁止审核。
- 历史图片归档总量 512 MB、大批图片原图引用的 32 条限制。磁盘写入失败时保留原历史，回退至未压缩内容，不删除用户原图。
- Android Shell 命令的 16K 字符、120 秒上限。`timeoutMs` 缺省或 0 不设期限，正数尊重调用方选择。USB 桥改用 UTF-8 长度帧，不再受 `writeUTF` 限制；已连接桥不因空闲或长命令自动断开。升级后需重新启动旧 USB 桥。
- Antigravity 单任务 1 小时、工具等待 180 秒截止，以及本地图片额外的 16 MiB 拒绝条件。取消仍有效。
- 插件发现只取前 128 个、每插件 32 个工具、回复 32 条文本、描述 / schema 配额、30 秒执行上限和默认 10 秒截止。显式插件期限不再因排队被耗尽。
- 文件预览 / 编辑固定 256 KiB 门槛，改为设备堆容量预算；普通源码文件不因超过 256 KiB 而被拒绝。
- Antigravity 历史只同步官方第一页；现在遍历官方游标，再供客户端分页。重复游标明确报错，避免无限循环。

## 仍保留的边界

| 边界 | 依据与行为 |
| --- | --- |
| 单条 JSON-RPC 128 Mi 字符、ACP 128 MiB、历史请求体 128 MiB | 整条 JSON 仍在内存解析；不是聊天条数或总历史配额。支持的历史接口按游标分页。后续应改进流式读取。 |
| 历史单图 64 MiB、解码像素 1 亿 | 控制原图 / Base64 / 位图的驻留内存。压缩不支持的图片保留原内容，不中断任务。实时观察未改动。 |
| 当前观察原图缓存 20 MiB、30 秒、单帧 | 临时内存证据，画面变化也会失效；仅影响同帧复核，绝不作为点击许可。历史原图不受 30 秒限制。 |
| 辅助预读 12 秒、4 MiB 图片、摘要长度 | 可选事实摘要，超时或超量回退主模型 / 原图，不阻断主任务，也不给预读器判断和操作权限。 |
| 文本 / 插件清单读取预算为当前剩余堆的 1/8 | 读取中逐块检查，为字节副本、解码和界面保留内存。文件增长或提供者不报长度也不会无限读入；导入、引用不受此读取预算限制。此预算降低内存耗尽风险，不承诺任意大 JSON 或编辑布局都能容纳。 |
| 插件内联请求 64 KiB / 回复 128 KiB，4 个并发位置 | Messenger 的 Bundle / Binder 传输成本；超量报错，排队不丢调用。v1 尚缺文件 / URI 大结果通道。 |
| USB / Shizuku / root 的 stdout 48,000 / stderr 12,000 字节摘录 | 共享执行服务的结果须经过 Binder；超量明确标记 truncated。大量输出应写文件再分段读，完整结果读取接口仍可完善。 |
| 无线 ADB 累积输出 24 MiB，单帧 16 MiB | shell-v2 输出当前在内存收集。已去掉额外的 48K / 12K 静默截断；超过收集预算明确报错。 |
| 截图、连接、健康检查和 HTTP 头的超时 / 格式边界 | 检测失联、损坏和系统截图频率；不等于任务总时长限制。 |
| 当前授权、活动任务、路径、插件身份和操作审批 | 防止失效任务、已撤销插件或其他项目继续操作。锁屏、系统授权、密码 / 验证码、支付等交接规则仍保留。 |
| 通知、悬浮预览和日志的简略展示 | 这些界面显示摘录，完整聊天不跟随摘录裁剪。 |

0.20.2 自检复现了取消截断后大回复直接布局导致的内存崩溃，现改为明确的行内预览和全文分页 / 搜索 / 导出，原始内容完整保留。队列和附件按可见位置创建界面。插件连接测试保留 5 秒健康检查期限；用户明确停止 Antigravity 后等待确认 5 秒，失联时关闭引擎，不自动重试或继续队列。这些期限不作用于正在正常执行的任务。后台保活采用任务期间续期的有限 OS 租约。详细依据见 [自检记录](limit-selfcheck.md)。

这是本轮审计记录，不宣称 Android / 上游运行时没有任何限制。插件大结果传输、Shell 完整结果分页和巨大 JSON 流式读取仍待完善。真机验证需手动进行，本轮不操作用户手机。

0.21.0 又实测发现 Codex 原生默认工具输出预算会从 JSON 中间裁剪屏幕报告。客户端现在在新建 / 恢复会话中，为没有显式 `tool_output_token_limit` 的账户 / 项目提供高于传输内存边界的预算，避免隐式裁剪。用户显式设置继续保留；模型上下文与传输内存边界仍适用。[官方配置说明](https://learn.chatgpt.com/docs/config-file/config-reference#tool_output_token_limit)。这不是预读规划或自动操作权限的变化。
