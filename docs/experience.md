# 旧尝试留下的经验

2026-10-30 检查旧 Codex Mobile 0.2.0 的源码、测试和文档后记录。这里只继承经验；当前业务实现和前端重新编写。旧版文档中的真机 / 模拟器结果不视为新版本的测试结果。

| 经验 | 对新实现的影响 |
| --- | --- |
| Android 10+ 限制从可写 App 数据目录执行程序 | 将第三方 ELF 作为 APK 的 native libraries 安装，PRoot 将它们映射到 guest 路径。可写工作区、账户与 guest 系统分开保存。 |
| Linux guest 的 DNS / VPN 路径与 Android 应用可能不同 | 在 Android 进程提供认证的 loopback CONNECT 隧道。TLS 不在 App 中解密，Codex 使用 Android 创建的网络连接。 |
| 浏览器 localhost 回调容易受到环境影响 | 设备码登录作为首要入口，先显示验证码，再由用户打开浏览器。 |
| Activity 生命周期不能代表任务生命周期 | 服务持有引擎、事件状态与待审批请求；旋转或离开页面不应丢失审批。 |
| 流式 delta 和最终 item 不能各追加一遍 | 用 item ID 更新同一条消息，最终 item 覆盖流式内容。 |
| 无线调试配对码窗口不能随意关闭 | 用通知 RemoteInput 输入验证码。配对端口、连接端口分开处理；Android 14+ 订阅服务信息更新。 |
| LibADB 的 InputStream 包装层可能在关闭时截断数据 | 直接读取 AdbStream，并解析 shell-v2 stdout / stderr / exit 帧。截图保留二进制字节。 |
| 连接系统能力不等于允许 Agent 操作 | 连接状态与操作许可分开。新项目允许无障碍 / 无线调试并行连接，屏幕操作与 Android Shell 分别授权，停止环境会撤销许可。 |
| 截图坐标不能跨旋转或旧画面复用 | 动作绑定 frame ID、尺寸、旋转与 30 秒有效期，完成动作即作废。 |
| 旧界面组织不代表新产品方向 | 新界面参考实际 DSH-Go / ChatGPT 手机截图，以对话为中心，不保留旧版页签和首页布局。 |

这次新发现：0.165.0 的协议 schema 中存在 `thread/items/list`，但本机 app-server 实测返回 `-32601`。因此必须以真实运行结果判断可用能力，并保留有针对性的历史读取回退。

模拟器验证还发现：默认 `uiautomator dump` 会暂时抑制其他无障碍服务。测试屏幕观察时应避免一边使用它一边判断连接状态；本次用普通 ADB 截图验证了无障碍截图结果。初始模拟器的 `ro.adb.secure=0`，无线调试配对认证不可用。本轮改用启用认证的独立可写 AOSP 测试镜像，已实际完成通知配对与 TLS ADB 连接。

## 0.1.1 的实际运行发现

- Android 的 `JSONObject.optString()` 可能把 JSON 空值呈现为字符串 `null`。可选标题和账户字段需先检查空值，再回退到合适的内容。
- 对话滚动跟随应保存用户的阅读意图。用旧布局索引与新消息数量比较，或切换页面时重建列表状态，会让新回复留在屏幕下方。
- 关闭子进程会中断日志管道读取。日志协程需要处理该正常关闭，否则未捕获的 `InterruptedIOException` 会使 App 崩溃。
- 图片工具回复可能较大。JSON-RPC 写入通过有界 IO 队列执行，避免子进程管道反压阻塞界面线程。
- 无障碍和无线调试并行可用，屏幕操作与 Android Shell 的许可分别控制。端到端检查验证了关闭 Shell 后，截图仍能返回 Codex。

## 0.2.0 的实际运行发现

- 版本命令成功不足以证明工具可用，需运行实际文件流程。Git 初始化在 App 进程中暴露出 `rename` 返回 ENOSYS 的问题，而从 ADB `run-as` 启动同一套环境可以成功，两种启动上下文不能等同。
- 移除强制设置的 `PROOT_NO_SECCOMP=1`，使用 PRoot 默认路径。上游 [同类问题及维护者说明](https://github.com/termux/proot/issues/390#issuecomment-5805680997) 也指出该环境变量只应用于有针对性的调试。回归检查必须由 APK 中的 Codex 执行 Git 初始化和 diff。
- 端到端测试的成功标记必须取自实际 `function_call_output`，请求本身包含测试代码和标记，不能将其当作执行证据。
- JSON-RPC 握手成功还不代表可以开始操作。账户、模型与上次对话都恢复后才显示就绪，并同步按钮与服务端守卫；否则恢复期间的新建会被忽略，随后发出的消息可能继续旧会话。
- 键盘弹出和 bring-into-view 也会触发列表滚动，不能把所有滚动都当成用户阅读意图。跟随状态依据实际拖动，且需在视口高度变化时重新定位最新回复。
- 侧栏使用稳定 item key 时，顶部插入新会话会保留原首行的位置，新行可能留在视口上方。打开侧栏时按当前会话定位；搜索则回到匹配结果顶部，不能用额外的会话索引掩盖滚动问题。


## 0.4.0 的恢复与审批发现

- 网络丢失回调中立即读取 `activeNetwork` 可能观察到旧状态。跟踪当前默认网络身份，直接处理丢失事件，并防止旧网络的丢失覆盖新连接。设备有默认网络仍不等于模型服务可访问。
- RPC 的局部超时会抛 `TimeoutCancellationException`，不能与用户停止导致的外部协程取消一并忽略。调用方仍活跃时应进入明确的失败状态。
- 原生 `apply_patch` 审批需要按 item 关联文件改动。差异截断必须显式提示，超限 / 缺失时服务也要拒绝直接批准；长差异的提示应位于内容之前。
- 仅根据 feed 条数 / 最后文字滚动，会早于 LazyColumn 的新项测量；异步文件卡片还会改变旧项高度。跟随最新需要观察实际项数、可继续滚动状态和尺寸变化，同时保留用户手动拖动的阅读意图。

## 当前实现保留的经验

- DSH-Go 的[执行过程](https://github.com/ccch1mneyyy/dsh-go/blob/main/docs/assets/f-steer-zh-light.webp)将当前动作、待发送输入、过程摘要和文件交付分开呈现；参考这种关系，让文件能直接预览、导出和分享，不移植其前端代码。早期对照基于 [d38a39a](https://github.com/ccch1mneyyy/dsh-Go/commit/d38a39acf8f5614619b609fb9c9791630928b944) 附近的作者资料，未实测上游 APK。
- 执行状态和浏览状态需要分开。读取 B 的历史不能恢复 B 或改变 A 的事件、审批、队列和文件归属；返回通知也要绑定任务标识。
- 首个原生会话 ID 分配会改变草稿归属，但不能重建输入框并丢失焦点。只按会话保存阅读区域；材料归属只迁移一次。
- Material 抽屉会请求初始焦点，搜索框可能自动弹键盘。将初始焦点放在容器，搜索时折叠导航，并给历史列表保留空间。
- 悬浮对话直接订阅执行 StateFlow，不能只在集中 publish 时更新；逐字 Timeline 更新可能绕过 publish。
- 通知与悬浮输入要绑定服务实例、引擎代数和会话修订；首个原生 ID 分配可以跟随，切换目标或重启不能把旧输入发到新目标。先持久保存，再发送；不确定输入留待用户检查。

- 通知不能只按通用 Android 截图推断体验。Shizuku 13.6.0 的 [AdbPairingService](https://github.com/RikkaApps/Shizuku/blob/v13.6.0/manager/src/main/java/moe/shizuku/manager/adb/AdbPairingService.kt#L259-L316) 使用 RemoteInput；输入阶段只留一个回复动作、复用 PendingIntent，呈现由 SystemUI 决定。不能将其等同于自定义 EditText，也不能对所有厂商断言一定额外点按。
- 连接能力与 AI 执行许可应独立。四种 Shell 可以保留连接，选中方式明确，切换关闭旧执行许可；Computer Use 的无障碍和无线实现继续互补并开。

后续缺口统一维护在 [roadmap.md](roadmap.md)，不再按每次迭代复制一份复盘。

## 预读取实验（0.10.0）

网页可以通过 WebView 暴露无障碍语义，但这不代表拿到了 DOM。输出必须标明来源、是否附图、截断与视觉限制；保留原图供主代理复核，先用真实模型评估后再决定是否增加 OCR / 小模型。预读取只提供事实，不能暗中承担任务规划与执行。

自绘控件往往只暴露 `android.view.View`，不能只靠名称中的 Canvas / SurfaceView 判断视觉内容。大块无标签叶节点应保守附图；结构读取仍不能保证完整描述画面。截图与节点读取期间的界面更新需要有限等待重试，旧帧仍需失效。

自指向 instrumentation 会重启自己的测试应用，所以测试网页必须放在独立的夹具应用。页面切换还应明确重建 Activity，避免新 Intent 继续显示旧内容；测试应核对真正送进 Codex 的工具结果，而非仅检查 App 本地预览。

Android 会对同一应用的通知更新限流，最后一次状态可能也被丢弃。只在每次状态变化时立即刷新，会留下“回复完成却仍在处理中”的旧通知；应合并刷新并保留最后状态，用真实 System UI 内联回复验证。

## 预读完整性与性能边界（0.11.0）

图片的 alt / contentDescription 可能只是一句标题，不能因此省掉较大图像的像素；纯表单则应先补齐 hint、占位状态、错误和数值，而非因为空文本就立即认定无语义。占位提示必须与实际输入区分。

当前根节点只覆盖一个窗口。输入法、分屏、浮窗以及模态页面周边的画面可能不在语义树里；应明确报告覆盖范围并保守附图。系统窗口枚举仅包含可交互窗口，不能把成功枚举当成全屏视觉完整的证明。

把 PNG 编码移出主线程后，界面事件能在编码期间到达，因此编码完成后还要检查 revision / rotation。只在编码前检查会产生新的时间窗口。计时也应区分最后一次成功尝试和含重试的总耗时，不能展示一个只计成功尝试的漂亮数字。


## 多截图历史恢复（0.12.1）

不能用单次截图的体积推断完整历史的 RPC 大小。0.165.0 的 `thread/read` 回退一次返回所有轮次，旧 16 Mi 字符限制会在恢复一段多截图对话时关闭连接，随后的列表请求又把原因覆盖成“请先启动本机环境”。上限提高到 128 Mi 字符，并在启动步骤之间检查连接；列表本身的错误留在侧栏重试。

模型 Context 与展示用 History 的图片不是同一份。本次真机记录的 Context 图片为 931×2048，UI 工具记录仍为 1440×3168 PNG。界面恢复成功、原生模型已缩图、旧图能够按需重读高清，是三种不同的能力，不能混为一谈。实时观察质量保持不变；未来的历史压缩应保留持久原图引用，不直接重写用户的原始会话。

## 轻量模型辅助预读（0.12.0）

复用 Codex 登录时，辅助模型仍应有独立的模型选择、临时会话和客户端处理器。只发送当前截图与节点，不额外提供任务 / 历史；当前画面里原本可见的内容仍会进入截图。角色约束不能只靠提示词，还要关闭工具并拒绝动作字段。只读沙箱仍可能允许运行只读命令，不能等同于“没有操作工具”。

0.165.0 的会话会重新加载配置。原生探测中，工具列表为空并不意味着 MCP 启动命令没有运行；只传空 MCP 表或仅关闭进程配置都不够。应显式禁用每个有效 MCP 名称，并把约束同时写入 CLI 和会话配置。固定版本仍需检查实际请求中的工具集合，不能把某个配置项存在当作执行约束已经生效。

临时客户端 stderr 的排空协程不能属于等待模型结果的限时作用域，否则作用域返回要等排空结束，而排空又要等 finally 终止进程，形成等待环。排空归外层资源作用域；清理先终止进程再关闭管道，取消 / 超时也应测试。

自动观察中，完整语义直接给主模型；必须附图的截断 / 窗口问题也不额外花一次辅助调用。只让辅助模型补读可补充的画面，显式测试才强制调用。即使 JSON 合格也不证明内容正确，原始节点和原图入口都应保留。调用链测试与真实模型质量 / 成本评估是不同证据，发布时必须说明。


## 历史图片分层（0.13.0）

0.13.2 的实际使用反馈表明，不能把截图证据的有效期当作点击许可。光标、刷新计时和动画都会触发内容变化，而一次点击本身也会清掉证据，导致连续点击 / 点击后输入无法完成。动作不再检查旧 frameId、截图年龄或内容 revision，路由也不再绑定最后一帧；仅当前显示范围检查坐标。同帧原图缓存与辅助预读结果仍校验新鲜度，避免把另一帧图片或过时辅助输出冒充当前证据。动态夹具需真实检查按钮计数与输入框，而非只看工具返回 success。

0.13.0 的隔离历史检查只覆盖自定义服务，漏掉内置 `openai` 的保留 ID 校验，导致真实账号新建 / 恢复对话失败。0.13.1 改为官方支持的 `openai_base_url`，不能套用自定义服务嵌套表，也不能仅把服务换个名字而丢失原生身份。新增 `--builtin-openai` 夹具用明确的假 API key 和 localhost 验证真实内置服务、原生 HTTP 回退及新建 / 恢复链路；与自定义服务分别出报告。假 key 不能证明真实 ChatGPT OAuth / workspace routing 已通过。[官方配置说明](https://learn.chatgpt.com/docs/config-file/config-advanced)。

界面历史、原生内存和实际模型请求是三层。只移除 App 里的 Base64 不会减小模型输入；请求层改写也不能宣称裁剪了原生磁盘或全部内存。原始会话保留，图片另建内容寻址存档，可回退、可校验；已丢失的源像素不能靠放大恢复。

固定版本的原生 config/read 会返回 `aws: null` 等显式空值，不能用字段存在判断某种 provider 已配置。API 的扁平配置键也不采用 CLI TOML 引号解析：`model_providers."name".base_url` 会产生带引号的新 provider。使用嵌套表并实测深度合并，避免替换掉认证字段。MCP 工具可能以 namespace 公开；夹具必须携带 function_call.namespace，不能只按平面名称查找。

原生环境和图片缩放提示也可能使用 role=user。用“最后一条 user 消息”判断图片是否历史会误压缩实时画面；应标记真正的当前任务，并在 UI 归并时隐藏自己的元数据，避免重复用户消息。原图重读要验证原生图片预处理后的最终请求，而非仅检查本地返回 URL；读取过去的像素应清掉实时图片缓存，不能把缓存清除当作拒绝动作的理由。

隔离检查的 am force-stop 会断开无障碍，恢复界面与读取历史成功不表示无障碍已重新绑定。需要继续截图的模拟器阶段应显式重新启用测试服务；这不是请求控制真实手机的理由。用户要求停止操作真实手机后，后续只使用 emulator-5560，自行安装与账号验证交给用户按步骤完成。

## 一次系统授权即可使用（0.14.0）

用户实际卡在重复配置，而非缺少权限说明。系统授权并连接后，不应再用另一组“向 AI 提供授权”开关重复阻断。可用性由真实连接、引擎状态与本次暂停生成；断线是暂时不可用，不能偷偷保存成用户主动关闭。连接恢复直接可用，显式暂停仍要保留到用户恢复或新的一次引擎使用。

悬浮窗的“用户希望显示”与“系统当前允许显示”不能合并为一个布尔值。权限暂时被撤销或 WindowManager 添加失败时保留偏好，恢复后再检查；用户明确关闭才保存关闭。首次已授予系统权限且没有关闭选择时直接显示。

端到端检查应在完全不触碰 AI 许可开关的条件下发起真实原生手机 / Shell 工具，并验证冷启动的连接恢复。UI 配置变化会重建 Activity，重要面板用 rememberSaveable 保存；深色图标需对实际 Window Insets 设置，不能只改 Compose 色板。

## 控屏提示按实际调用显示（0.15.0）

一轮任务包含读取、模型思考、工具调用和等待用户多个阶段，蓝色“正在控屏”提示只覆盖真正接触屏幕的调用。把提示放进后端 execute 的作用域，能让本地观察测试、真实模型调用与 ADB 回退使用同一生命周期；辅助模型等待在观察返回后运行，不会让蓝框整轮常亮。缓存图片不等于重新观察屏幕。

被动提示与已有任务控制 / 聊天悬浮窗分开。触摸穿透需要遵守 Android 12+ 对普通覆盖层的透明度规则；无障碍窗口复用系统 grant，不应再增加 App 内 AI 授权开关。退出必须同步移除，引用计数 / 唯一租约避免旧任务的 finally 影响新任务。

## 文字密度与实际操作（0.16.0）

重复解释连接、授权与启动会让用户看不出该点哪里。常用页展示当前状态和可做的动作，技术细节放进展开项，影响数据 / 任务的说明留在确认时。功能颜色与标题大小应服务于层级，不能只靠增加说明。

大字号需要改变排版：窄卡片会产生孤字，滚动内容里的关闭按钮也可能离开视野。模拟器实际检查后，首页使用宽动作行，连接方式回退单列，快捷控制固定标题和关闭按钮。
